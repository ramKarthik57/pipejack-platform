# PipeJack Threat Model & Security Boundaries

## 1. Threat Environment & Trust Boundaries

The continuous integration and build environment occupies an ambiguous security zone. Unlike production runtime environments where containers run locked-down services with minimal privileges, build nodes execute arbitrary compilation scripts and untrusted third-party dependencies (`npm`, `pip`, `maven`).

### Trust Boundaries:
1. **Adversary Zone (Untrusted Build Workspace)**:
   - Source code submitted by developers.
   - Third-party packages, libraries, and compilation plugins.
   - Lifecycle scripts executing with container privileges during compilation.
2. **Container Boundary (Linux cgroup v2 & netns)**:
   - Docker container executing the build.
   - Process IDs isolated via pid namespace.
   - Virtual network interface attached to container netns.
3. **PipeJack Security Zone (Host-Level Daemon & Orchestrator)**:
   - Host kernel `/proc` filesystem and cgroup v2 scopes (`/sys/fs/cgroup`).
   - Host `iptables` kernel firewall.
   - Host filesystem `/workspace` and attestation ledger `/home/ubuntu/pipejack-attestations`.
   - Host Docker engine socket `/var/run/docker.sock`.
   - Ed25519 asymmetric private signing key.

## 2. Attacker Capabilities & Assumptions

We assume an adversary with the following capabilities inside the build workspace:
- Can modify dependency manifests (`package.json`, `pom.xml`, `requirements.txt`).
- Can execute arbitrary commands as the user inside the container via lifecycle hooks (`postinstall`, `setup.py`, custom Maven build steps).
- Can attempt to spawn interactive shells (`/bin/sh`, `/bin/bash`).
- Can attempt to exfiltrate environment secrets or source code via network utilities (`curl`, `wget`, `python` sockets).
- Can attempt to modify source files in place or inject backdoors into binaries prior to container image creation.

We assume the following host invariants hold true:
- The host Linux kernel and Docker daemon have not suffered a container breakout vulnerability (e.g., runc CVE-2019-5736).
- The host-level PipeJack daemon and orchestrator process are running with appropriate host privileges.
- The private signing key (`ed25519.key`) is stored on the host filesystem and never mounted into worker containers.

## 3. STRIDE Threat Analysis

| Threat Category | Attack Vector | PipeJack Countermeasure | Residual Risk / Limitation |
| :--- | :--- | :--- | :--- |
| **Spoofing** | Attacker tampers with build provenance record or forges attestation. | Every build record is digitally signed with host Ed25519 key and chained via SHA-256 `prev_hash`. | Host compromise allows key theft. Hardware TPM integration recommended for enterprise deployments. |
| **Tampering** | In-situ source tampering during build (e.g., injecting backdoor into `.java` or `.py` source file). | Pre/post-build Merkle tree calculation (`fschecker`). Any change outside allowed compiler directories (`target/**`) halts the build. | Very rapid in-memory compilation without disk writes would require memory instrumentation. |
| **Repudiation** | Attacker claims a rogue image was legitimately generated by the CI. | Ledger records full build hash, timestamp, commit context, and PDP verdict. Only unquarantined images with verified signatures are valid. | None within the ledger scope. |
| **Information Disclosure** | Build script reads environment variables or files and exfiltrates via HTTP/DNS. | Dedicated container netns `PIPEJACK_EGRESS` iptables chain drops outbound traffic. Passive socket monitor catches unauthorized socket attempts. | Covert timing or side channels; out-of-band CPU cache channels not mitigated. |
| **Denial of Service** | Malicious build forks thousands of processes or consumes infinite CPU/disk. | Docker container cgroup limits enforce CPU/memory quotas; `proctree` monitors process counts and reports anomalies. | Resource exhaustion can slow build node; mitigated by container resource constraints. |
| **Elevation of Privilege** | Malicious build script attempts to gain host privileges or break out of container. | Containers run without `--privileged` and without host root filesystem mounts. Docker socket is never mounted into container. | Linux kernel zero-day privilege escalation vulnerabilities. |

## 4. Security Invariants & Policy Enforcement

PipeJack enforces three non-negotiable security invariants on every build:

1. **Process Allowlist Invariant**:
   No process whose canonical executable path does not match the declarative policy allowlist may execute inside the container cgroup. Any unauthorized executable triggers an immediate PDP `BLOCK`.

2. **Filesystem Immutability Invariant**:
   Source files present at build inception must remain bit-for-bit identical at build completion. Only files matching explicit output globs (e.g., `target/*.jar`) may be introduced or altered.

3. **Egress Lockdown Invariant**:
   Containerized build processes must not establish outbound network connections to arbitrary external IP addresses. Build dependencies must be pre-cached, vendored, or retrieved through verified upstream mirrors.
